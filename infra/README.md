# Deploying Make My Marriage

What runs where (System Design §19):

| Piece                       | Where                                      | Files                                                |
| --------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| Website (`apps/web`)        | Vercel, functions in Mumbai (`bom1`)       | [apps/web/vercel.json](../apps/web/vercel.json)      |
| API and worker (`apps/api`) | One AWS EC2 server in Mumbai, behind Caddy | [apps/api/Dockerfile](../apps/api/Dockerfile), below |
| Database                    | MongoDB Atlas, Mumbai                      |                                                      |
| Email                       | Resend                                     |                                                      |

On the server, [docker-compose.prod.yml](docker-compose.prod.yml) runs three containers: Caddy
(HTTPS, [Caddyfile](Caddyfile)), the API and the worker. The API and the worker are one image
with two commands. The server keeps nothing important on its disk: sessions, rate limits and jobs
are all in the database.

Never put a password, key or connection string in the repository (it's public). They go only
into `apps/api/.env` on the server and into Vercel's settings.

## Before the domain is set up

Everything can be set up and checked without a domain, using two free addresses:

- the website at `https://<project>.vercel.app`;
- the API at `https://<server-ip-with-dashes>.sslip.io` (sslip.io turns `13-235-10-20.sslip.io`
  into the IP address `13.235.10.20`, so Caddy can get an HTTPS certificate for it).

`https://<project>.vercel.app/status` then shows whether the website reaches the API and the API
reaches the database. **Logging in needs the domain**: the website and the API share the login
cookie only when both are under one domain (`makemymarriage.com` and `api.makemymarriage.com`).
Until then Resend also sends only to the email address its account was opened with.

## 1. MongoDB Atlas

1. Sign up at [mongodb.com/atlas](https://www.mongodb.com/atlas) and create a project
   ("Make My Marriage").
2. Create a cluster: **Free** for now (M10 before real families use it), provider **AWS**,
   region **Mumbai (ap-south-1)**.
3. Database access: add a user (for example `mmm-app`) with an autogenerated password (letters
   and digits only) and the role "Read and write to any database". Keep the password safe.
4. Network access: add the server's fixed IP address once you have it (step 2). Never allow
   `0.0.0.0/0` (everywhere). Remove any address Atlas added for your own computer if you don't
   need it.
5. Connect → Drivers: copy the connection string and put the database name before the `?`:
   `mongodb+srv://mmm-app:<password>@<cluster>.mongodb.net/makemymarriage?retryWrites=true&w=majority`

## 2. The AWS server

1. In the AWS console, choose the region **Asia Pacific (Mumbai) ap-south-1** (top right).
2. EC2 → Launch instance:
   - Name `mmm-api`; image **Ubuntu Server 24.04 LTS**, architecture **64-bit (Arm)**;
   - Instance type **t4g.small** (t4g.medium at launch);
   - Key pair: create one (ED25519, `.pem`) and keep the file safe;
   - Network: allow SSH from **My IP** only, and HTTP and HTTPS from the internet;
   - Storage: 20 GiB gp3.
3. EC2 → Elastic IPs → Allocate, then Associate it with `mmm-api`. This is the server's fixed
   IP address; add it to Atlas (step 1.4).
4. Billing → Budgets: a monthly budget (for example $25) with an email alert.

## 3. Resend

1. Sign up at [resend.com](https://resend.com) with the email address you'll log in with while
   testing.
2. API Keys → Create, with "Sending access". It's shown once; keep it safe.
3. Until the domain is set up, emails go out from `onboarding@resend.dev`, to your address only.

## 4. Vercel

The website builds from GitHub, so the branch Vercel uses must already contain
`apps/web/vercel.json`.

1. Sign up at [vercel.com](https://vercel.com) with **Continue with GitHub**, as **ankitsaini001**.
2. Add New → Project → import `ankitsaini001/namaste-ai`.
3. **Root Directory: `apps/web`.** Framework: Next.js. Leave the build and install commands as
   they are: `vercel.json` builds `@mmm/shared` first and puts the functions in Mumbai, and
   `apps/web/package.json` asks for Node.js 24.
4. Environment variables, both `https://<server-ip-with-dashes>.sslip.io` for now:
   `NEXT_PUBLIC_API_URL` and `API_URL`.
5. Deploy, and note the website's address (`https://<project>.vercel.app`): the server needs it.

Vercel deploys the production branch (GitHub's default, `dev`) on every push, and gives every
other branch a preview link. Previews can't log in: the API accepts only the one address in
`WEB_ORIGIN`. `NEXT_PUBLIC_API_URL` is built into the website, so after changing it, redeploy.

## 5. Start the API on the server

Connect with `ssh -i <key>.pem ubuntu@<server-ip>`, then:

```sh
# Swap, so building the image doesn't run out of memory on 2 GB.
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Docker, then log out and in again so "docker" works without sudo.
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu
exit
```

```sh
git clone https://github.com/ankitsaini001/namaste-ai.git && cd namaste-ai
cp apps/api/.env.example apps/api/.env && chmod 600 apps/api/.env
cp infra/.env.example infra/.env
openssl rand -hex 32            # copy the output into LOGIN_CODE_SECRET below
nano apps/api/.env              # the settings below
nano infra/.env                 # API_HOST=<server-ip-with-dashes>.sslip.io

docker compose -f infra/docker-compose.prod.yml build
docker compose -f infra/docker-compose.prod.yml run --rm api node dist/migrate.js
docker compose -f infra/docker-compose.prod.yml up -d
curl https://<API_HOST>/v1/health/ready
```

`apps/api/.env` on the server (replace everything in the file; comments on their own lines):

```sh
NODE_ENV=production
# The website's address: https://<project>.vercel.app, later https://makemymarriage.com
WEB_ORIGIN=https://<project>.vercel.app
MONGODB_URI=mongodb+srv://mmm-app:<password>@<cluster>.mongodb.net/makemymarriage?retryWrites=true&w=majority
LOGIN_CODE_SECRET=<output of openssl rand -hex 32>
COOKIE_SECURE=true
# Once the domain is set up:
# COOKIE_DOMAIN=.makemymarriage.com
# Caddy is in front of the API, so rate limits see each visitor's address.
TRUST_PROXY=loopback, uniquelocal
EMAIL_TRANSPORT=resend
RESEND_API_KEY=<from Resend>
# Later: Make My Marriage <no-reply@mail.makemymarriage.com>
EMAIL_FROM=Make My Marriage <onboarding@resend.dev>
EMAIL_DAILY_LIMIT=100
EMAIL_RESERVED=20
```

Leave `EMAIL_CODE_IP_LIMIT` out (10 login codes per IP address an hour). `PORT` is set by the
compose file.

## 6. Check

1. `curl https://<API_HOST>/v1/health/ready` shows `"database":"up"`.
2. `https://<project>.vercel.app` shows the homepage, and `/status` shows the API and MongoDB
   as working.
3. With the domain: log in with a real email, set up a test wedding, invite a second address as
   an organiser.

## Everyday work on the server

```sh
cd ~/namaste-ai
C="docker compose -f infra/docker-compose.prod.yml"

# Deploy new code: build, apply migrations, restart what changed.
git pull && $C build && $C run --rm api node dist/migrate.js && $C up -d

# After changing apps/api/.env or infra/.env
$C up -d --force-recreate

$C ps                    # what's running
$C logs -f api worker    # follow the logs
```

## When the domain is ready

1. Vercel → Settings → Domains: add `makemymarriage.com` and `www.makemymarriage.com`, with
   `www` redirecting to the main address, and add the DNS records Vercel shows.
2. DNS: an `A` record for `api.makemymarriage.com` pointing at the server's fixed IP address.
3. Resend → Domains: add `mail.makemymarriage.com` and its DNS records, and wait until it's
   verified.
4. Server: in `infra/.env`, `API_HOST=api.makemymarriage.com`; in `apps/api/.env`,
   `WEB_ORIGIN=https://makemymarriage.com`, `COOKIE_DOMAIN=.makemymarriage.com` and
   `EMAIL_FROM=Make My Marriage <no-reply@mail.makemymarriage.com>`. Then
   `docker compose -f infra/docker-compose.prod.yml up -d --force-recreate`.
5. Vercel: set `NEXT_PUBLIC_API_URL` and `API_URL` to `https://api.makemymarriage.com`, then
   redeploy.
